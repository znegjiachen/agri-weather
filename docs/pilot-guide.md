# 小范围试点指南

目标：用 5~10 位真实农户、2~4 周，拿到可写进答辩的“使用数据 + 典型故事”，而不是编造数字。

## 一、试点对象

- 1~2 个村/合作社，作物集中（水稻、蔬菜或果树任选一类）
- 至少 3 位会用智能手机的农户 + 1 位农技员
- 每户录入 1~3 块真实地块，录入作物和播种日期

## 二、伦理与隐私

- 事前说明：数据用于产品改进，不公开个人手机号和精确坐标
- 取得口头或书面同意；未成年人不在试点范围
- 农户可随时要求删除对话和文档；文档本身 7 天自动过期
- 展示给评委的案例做匿名化：隐去姓名、手机号，坐标只保留乡镇级

## 三、四周安排

| 周 | 动作 | 产出 |
|---|---|---|
| 第 1 周 | 培训录入地块、问 3 个真实问题 | 使用记录、问题清单 |
| 第 2 周 | 每天看一次预警；开启 Web Push | 预警触达/处理记录 |
| 第 3 周 | 上传种植方案/防治资料，试用文档问答 | RAG 使用记录 |
| 第 4 周 | 回访：哪些回答有用、哪些不敢信 | 满意度、改进项 |

## 四、要记录的数据

系统侧（可直接查询）：

- `agent_feedback`：点赞/点踩数量、点踩原因
- `/api/agent/metrics`：请求数、成功率、平均延迟、工具调用、知识命中、文档轮次、安全提示次数
- `agent_chat_message`：提问主题分布（脱敏后统计）
- `weather_alert`：预警数量、已读/已处理比例
- `push_subscription`：订阅人数（不代表送达数，送达需结合浏览器/服务端日志）

农户侧（访谈）：

- 本周用了多少次；最有用的一次是什么
- 有没有因为预警改变作业安排（提前防冻、推迟打药等）
- 哪些回答“听起来对但不敢照着做”
- 愿不愿意继续用；愿意付多少钱/由谁付费

## 五、建议指标

| 指标 | 计算方式 | 目标（示例） |
|---|---|---|
| 周活跃 | 一周内至少提问 1 次的农户 / 总农户 | ≥ 60% |
| 人均提问 | 总提问数 / 活跃农户 | ≥ 5 次/周 |
| 回答满意度 | UP / (UP + DOWN) | ≥ 75% |
| 工具调用成功率 | 成功工具调用 / 总调用 | ≥ 95% |
| 平均响应时间 | 后端指标 avgLatencyMs | ≤ 15s |
| 预警触达 | 收到推送并打开的农户 / 订阅农户 | ≥ 70% |
| 预警行动率 | 因预警调整作业的农户 / 收到预警的农户 | ≥ 30% |

没有达到目标也没关系，答辩时如实说明“试点样本小、结论是方向性的”，比编数字可信。

## 六、访谈提纲

1. 这周你用它问了什么？最有用的是哪一次？
2. 它给你的建议，你敢直接照着做吗？为什么？
3. 预警有没有帮你避免损失或提前准备？
4. 哪个功能最麻烦/最不信任？
5. 如果村里统一买，你觉得一年多少钱合理？

## 七、答辩可用的表达

> 我们在 X 村做了 4 周试点，Y 位农户、Z 块地，累计提问 N 次，回答满意度 P%，  
> 收到预警 M 条，其中 K 次农户据此调整了打药/防冻安排。  
> 样本很小，但验证了两件事：农户愿意用自然语言问农事，且地块级天气+预警比通用天气更有行动价值。

（以上数字请用真实试点结果替换；没有试点就明确说“尚未开展试点”，不要虚构。）
