# 演示视频稿（7 分钟版 · 全链路）

> 适用：网评提交 / 答辩前播放。
> 流程：注册 → 地图圈地 → 问「明天能打药吗」看工具轨迹 → 上传种植方案并追问 → 拍照识病 → 语音提问 → 手机收推送 → MCP 与 AI 安全评测 → 收尾。
> 配套：[拍摄指南](demo-video-guide.md)、[5 分钟现场答辩脚本](demo-script.md)。
> 本稿取代 [demo-voiceover-script.md](demo-voiceover-script.md) 作为录制用稿；旧稿仍可作旁白素材。

## 使用说明

- 每个场景单独录一段，文件名 `scene1`…`scene9`，剪辑按时间码对齐。
- 正常语速 230–250 字/分钟，全稿约 1750 字，约 7 分 10 秒。
- 括号里是操作与停顿提示，不念。
- 涉及具体数值（风速、降水、识别结果、指标数字）时，**以录屏当天的真实值为准**，旁白说「风速超过规则上限」这类结论，不要把示例数字念死。
- 术语读法：问田 `wèn tián`；助农手 `zhù nóng shǒu`；稻瘟病 `dào wēn bìng`；阈值 `yù zhí`；RAG 说「检索增强」；SSE 说「流式输出」；MCP 直接读字母。

## 录制前检查

- [ ] 站点走 HTTPS（语音识别、PWA、Web Push 必需；本地 HTTP 只录前四段）
- [ ] 演示账号干净：3 块地，至少一块水稻有边界、作物、播期；无 test/aaa 占位名
- [ ] 知识库预先上传 `docs/knowledge-samples/rice/` 下 2–3 份，并跑过一次检索测试
- [ ] 方案文件备好：`docs/plans/水稻早稻种植计划_2027.md`（或结构清晰的同类方案）
- [ ] 叶片照片备好并**提前试识别一次**，确认识别结果可讲；识别不准就换图
- [ ] 手机用同一账号登录，已允许通知；与电脑并排摆放，方便同框收通知
- [ ] MCP Server 已启动，Claude Desktop/Code 客户端已配置，预热调用过一次
- [ ] 智能体控制台指标面板非零：提前问几轮，让请求数、工具调用、知识命中都有数
- [ ] 天气接口预热一次（Redis 缓存命中）；地图目标区域瓦片预加载
- [ ] Chrome 独立配置，1080p、缩放 100%，关插件和书签栏；开鼠标高亮

## Scene 1｜0:00–0:20 注册与定位

（画面：打开注册页，填手机号、密码，提交，进入桌面驾驶舱）

这是问田。一个地块级的农事气象助手。

它不只播报天气，而是回答：这块地明天能不能打药，该不该防冻。

（停 0.5 秒）

---

## Scene 2｜0:20–1:10 地图圈地

（画面：打开地图，缓慢点边界点，围成多边形，保存；选水稻、填播期；回到地块列表）

先建地块。在地图上点几个边界点，围成多边形，面积由服务端重算。

选好作物和播期，保存后，这块地会自动生成一个专属的助农手。后面的天气、预警、农事建议，都绑定到它。

（停 0.5 秒）

土壤和灌溉建议也会按位置和作物自动带出。地图是卫星底图，边界随时能改。

切到地块列表，能看到作物、面积、种植天数和预警入口。多块地可以在左上角切换，驾驶舱跟着变。

---

## Scene 3｜1:10–2:40 Agent 工具轨迹（重点）

（画面：打开助农手，粘贴问题「明天适合给这块水稻打药吗？」，发送，等 2–3 秒）

现在问一个种地真会问的问题：明天适合给这块水稻打药吗？

模型没有直接编答案。它先确认地块，调用天气工具拿到风速和降水；再调农事规则，确认打药窗口；最后查生育期。

（展开「工作轨迹」，慢速滚动，在工具名和耗时处停一下）

这里每一轮都有思考、工具名、参数和耗时。风速、降水都来自真实接口，不是模型想的。

（停 0.5 秒）

规则判定风速超过上限，所以结论是不建议打药，并给出下一个可行窗口。

（停 1 秒）

追问一句「那后天呢」，能看到上下文延续，不用再报一次地块。

（画面：再发一条，展示回答）

工具报错时也一样：错误会作为结构化结果回给模型，让它换思路，不会把整轮对话打断。

---

## Scene 4｜2:40–3:50 方案任务与 RAG

（画面：地块「📒 记录」→「计划任务」→ 上传方案）

方案怎么落地？上传一份种植方案，AI 把播种、施肥、打药、收获这些任务抽出来，每条带来源。

但它不会直接写进待办，要先人工确认。

（画面：确认保存，展示时间轴；完成一条，打开农事记录）

确认后才入库，到期提醒。完成一条，自动生成农事记录，并统计完成率和按时率。

（停 0.5 秒）

（画面：回到对话，追问「这份方案里，稻瘟病在什么条件下容易发生？」）

再追问文档里的问题。回答下方会列出参考知识，说明这段来自哪份资料。

检索没命中就不注入，避免把无关内容塞给模型。临时文档保留七天，不进入长期知识库。

---

## Scene 5｜3:50–4:40 拍照识病

（画面：上传叶片照片，展示识别卡片）

再看识图。上传一张叶片照片，视觉模型先识别作物、生育期和可见病害，再把结果交给文本助手，结合地块天气给建议。

（停 0.5 秒）

置信度低的时候，它会明确说依据不足，建议补拍叶片正反面和整株，而不是硬下结论。

具体用药只提醒按农药标签使用，不编造浓度和剂量。

---

## Scene 6｜4:40–5:20 语音提问

（画面：点麦克风，说「这种情况要打什么药？」）

田里不方便打字，可以直接说。语音转成文字后，走的是同一套智能体、同一套工具和知识库。

（画面：识别结果自动填入并发送）

它接着上一张照片的上下文回答，不用重新描述病情。

（停 0.5 秒）

语音、PWA 和推送都要求 HTTPS，这也是上线时统一配好的。

---

## Scene 7｜5:20–6:00 预警与 Web Push

（画面：进入预警中心，点「检查全部地块」；手机同框弹出通知，点开）

预警不是气象局发布的，是平台按作物、生育期和未来二十四小时的温度、降水、风速算出来的阈值检查。后台每三十分钟自动跑一次。

（停 1 秒，等手机通知）

点「检查全部地块」，手机立刻收到系统通知，点开直达预警页。

页面也写明了：非官方发布，仅供参考。

---

## Scene 8｜6:00–6:50 MCP 与 AI 安全评测

（画面：切到 Claude Desktop，展示 agri-weather 工具列表，调用一次 `get_weather`）

同一套农事能力，也做成了标准 MCP Server。天气、地块、农事建议、作物检索都以 MCP 工具暴露，Claude Desktop 这类客户端可以直接调用。

（停 0.5 秒）

写操作必须两段式确认：先预览，再写入；每次调用都记审计日志。

（画面：切回智能体控制台指标面板）

AI 侧我们记录了对话请求、成功率、平均响应、工具调用和知识命中。RAG 评测 hit@5 是十比十，但样本只有十条，只作为链路验证，不写成田间效果。

（停 0.5 秒）

输出侧有安全兜底：高风险农药、绝对化承诺会追加安全提示；手机号和身份证号会自动隐去。

---

## Scene 9｜6:50–7:10 收尾

（画面：回到驾驶舱完整画面）

问田把天气、地块、作物和 AI 接到同一条链路上。

下一步，是把它放进真实田间使用。

（停 1 秒，结尾）

# 附录 A：MCP 展示准备

启动（二选一）：

```bash
# 已有 JWT
cd mcp-server
AGRI_TOKEN=你的JWT AGRI_API_BASE=http://localhost:8082 node server.mjs

# 或账号密码自动登录
cd mcp-server
AGRI_USERNAME=你的用户名 AGRI_PASSWORD=你的密码 AGRI_API_BASE=http://localhost:8082 node server.mjs
```

客户端配置（Claude Desktop / Claude Code）：

```json
{
  "mcpServers": {
    "agri-weather": {
      "command": "node",
      "args": ["D:/智慧农业天气系统/mcp-server/server.mjs"],
      "env": {
        "AGRI_API_BASE": "http://localhost:8082",
        "AGRI_TOKEN": "替换为你的 JWT"
      }
    }
  }
}
```

录屏时只演示只读工具，最稳：

1. `list_farmlands`：列出地块
2. `get_weather`：取某地块天气
3. `search_crops`：按名称检索作物

写入类工具（`create_farm_operation` / `create_season` / `create_reminder`）口头说明即可：必须 `confirm:false` 预览后再 `confirm:true`，审计日志默认写 `~/.agri-weather-mcp-audit.jsonl`。

# 附录 B：安全与评测口径（照这个说，别夸大）

| 说法 | 可以说的 | 不要说 |
|---|---|---|
| RAG 评测 | hit@5 = 10/10，10 条水稻问题，宽松命中口径 | 「准确率 100%」「top1 全对」 |
| 安全过滤 | 高风险农药、绝对化承诺追加提示；手机号/身份证自动隐去 | 「已杜绝幻觉」 |
| 指标 | 面板记录请求数、成功率、平均响应、工具调用、知识命中 | 把测试数据当生产数据 |
| 预警 | 阈值推导，页面标注非官方发布 | 「官方预警」 |
| 试点 | 如尚未开展，就说「下一步进田间验证」 | 编造农户数量和增产数字 |

# 附录 C：常见翻车与应急

| 问题 | 应急 |
|---|---|
| Agent 超时 | 提前预热；失败就重录这一段，不要拼接别的问题的答案 |
| 语音/推送用不了 | 只有 HTTPS 能录；没有就跳过并删掉对应旁白，不要假装演示 |
| 识别结果不准 | 换一张提前验证过的照片；旁白改说「识别置信度低时会提示补拍」 |
| 地图瓦片空白 | 提前加载目标区域；等瓦片缓存 |
| 任务抽取不理想 | 换结构清晰的方案文件，或只确认已有任务 |
| MCP 客户端没响应 | 确认 token 未过期、后端在跑；备用方案是展示 `mcp-server/test.mjs` 输出 |
| 指标全是 0 | 录制前先问 3–5 轮，让面板有数 |
