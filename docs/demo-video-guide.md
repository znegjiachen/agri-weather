# 演示视频拍摄指南（6–8 分钟版）

> 录制用稿：[演示视频稿 v2（7 分钟全链路）](demo-video-script-v2.md)。
> 目标：让评委在 6–8 分钟内看懂“问田解决什么问题、AI 怎么落地、工程上是否可信”。
> 不建议把 9 个功能平均分配时间。重点是地块驾驶舱、Agent 工具轨迹、RAG、任务闭环四段。

## 一、先定版本

| 版本 | 时长 | 适合场景 | 必须包含 |
|---|---|---|---|
| 答辩版 | 5–6 分钟 | 现场答辩前播放 | 首页、地块地图、Agent 轨迹、RAG、任务闭环 |
| 完整版 | 7–8 分钟 | 网评/提交材料 | 在答辩版上增加多模态、预警推送、工程与评测 |
| 精简版 | 3 分钟 | 初审/预告 | 首页、Agent 轨迹、任务闭环 |

建议录 **7 分钟左右**：比 5 分钟从容，又不会让评委在等待模型响应时失去耐心。

## 二、录制前准备

### 1. 环境

- 后端：`agri-weather-server`，默认 `8082`
- 前端：`weather-app-react`，默认 `5173`
- 数据库：MySQL 8；Redis 可选但建议开启，天气缓存和限流更稳定
- 必须配置：`DEEPSEEK_API_KEY`、`JWT_SECRET`、`DB_PASSWORD`
- 可选：`VISION_API_KEY`（识图）、`VAPID_*`（Web Push）、`ASR_*`（语音）

本地启动示例：

```bash
export DB_PASSWORD=你的数据库密码
export JWT_SECRET=$(openssl rand -base64 32)
export DEEPSEEK_API_KEY=你的密钥
cd agri-weather-server && ./mvnw spring-boot:run

cd weather-app-react && npm run dev
```

**HTTPS 提醒：** 语音识别、PWA 安装、Web Push 都要求 HTTPS。如果本地只有 HTTP：

- 核心流程（地块、天气、Agent、RAG、任务）照常录；
- 语音/PWA/推送单独在 HTTPS 环境录一小段，或直接不录，避免现场翻车；
- 不要在视频里声称“已演示”但实际没出现。

### 2. 演示数据

提前准备一个干净的演示账号，数据要能在一屏内看懂：

- 3 块地：水稻、玉米、番茄；至少一块有边界、作物和播种日期
- 不同生育期：一块收获期、一块生长中，便于展示阶段差异
- 预警：提前点一次“检查全部地块”，让预警中心有内容
- 任务：今日待办 2–3 条、未来任务 1–2 条
- 知识库：上传 2–3 份水稻/病害资料
- Agent：提前问一次“明天适合打药吗”，让对话历史里有工具轨迹

录制前把无关测试数据删掉，不要出现“test”“aaa”“1 号田”这类占位名称。

### 3. 浏览器与录屏

- 浏览器：Chrome 或 Edge，独立干净用户配置，关闭插件和书签栏
- 分辨率：1920×1080，缩放 100%
- 录屏：OBS Studio，1920×1080，30fps（或 60fps），H.264
- 音频：麦克风单独音轨，48kHz；开降噪；录前试录 30 秒回听
- 鼠标：打开“鼠标高亮”或后期加点击圈，评委才看得清你点了哪里
- 第二块屏：放逐字稿或分镜表，不要放在录制屏上

## 三、分镜与旁白（7 分钟版）

| 时间 | 画面 | 操作 | 旁白 |
|---|---|---|---|
| 0:00–0:25 | 桌面驾驶舱 | 停留在首页，鼠标轻扫天气、地块、预警、今日农事 | “这是问田。它不只想告诉你明天什么天气，而是回答这块地明天能不能打药、该不该防冻。” |
| 0:25–1:15 | 地块与地图 | 打开地图，缓慢圈一块地，保存；回到地块列表 | “先建地块。边界点围成多边形，面积由服务端重算；作物和播期确定后，系统自动生成这块地的专属助农手。” |
| 1:15–1:55 | 驾驶舱与预警 | 切换地块，打开 7 日趋势，进入预警中心 | “驾驶舱把天气、趋势、预警和今日农事放在一屏。预警不是官方信号，是平台按作物、生育期和未来 24 小时极值做的阈值检查。” |
| 1:55–3:25 | Agent 工具轨迹 | 打开助农手，问“明天适合给这块水稻打药吗？”；等待回答；展开“工作轨迹” | “模型先判断需要查数据，调用天气、农事规则和生育期三个工具；风速、降水和阶段都来自真实接口。这里能看到每一轮的思考、工具名、参数和耗时。” |
| 3:25–4:05 | 多模态（可选） | 上传一张叶片照片，展示识别卡片 | “照片先由视觉模型识别植物、阶段和可见病害，再交给文本智能体结合地块天气给建议。置信度低时会明确提示补拍。” |
| 4:05–4:45 | 播种适配 | 打开作物页，选择作物，展示 64 种作物和条件检测 | “播种适配把计划播期和实时气象对齐，给出温度、降水、光照、湿度的匹配度，并标注数据来源和置信度。” |
| 4:45–5:40 | 方案任务 | 上传种植方案，确认 AI 抽取的任务；完成一条任务，打开农事记录 | “方案不是停在聊天框。AI 抽取任务，人工确认后入库；到期提醒，完成后自动生成农事记录，并统计完成率和按时率。” |
| 5:40–6:25 | 知识库/RAG | 上传一份资料，问一个文档里的问题，展示“参考知识” | “每块地的知识库独立。上传时切块建索引，提问只检索相关片段，不把整篇文档塞给模型；没有命中就不注入。” |
| 6:25–7:05 | 工程与评测 | 切到技术文档第 14–16 页，快速展示公式、代码、评测表 | “工程上，CI 会跑后端测试和全新库迁移；AI 评测有检索命中率、Agent 场景和有无工具对照。样本小，所以我们只写成链路验证，不写成田间效果。” |
| 7:05–7:30 | 收尾 | 回到驾驶舱，停在完整画面 | “问田把天气、地块、作物和 AI 助手接到同一条链路上。下一步是把它放进真实田间使用。” |

## 四、关键镜头怎么拍

### 1. Agent 工具轨迹（最重要）

- 问题提前写好，直接粘贴，不要现场打字
- 问完先让“思考/工具调用”跑 2–3 秒，再展开轨迹
- 轨迹展开后**慢速滚动**，在三个工具名和耗时处停一下
- 模型耗时 7–14 秒很正常；剪辑时把空白等待压到 2–3 秒，但不要剪掉工具轨迹本身
- 如果第一次回答不理想，重开一轮，不要用剪辑拼接成“另一个问题”的答案

### 2. 地块圈选

- 圈一个形状规整、面积合理的多边形
- 保存后停 2 秒，让评委看清面积和自动生成的助农手
- 不要在现场改土壤、灌溉等表单，容易出错

### 3. RAG 文档

- 提前上传好资料，现场只演示“提问—检索—引用”
- 问题要能从资料里找到答案，例如“稻瘟病在什么温湿度下容易发生？”
- 回答后指向“参考知识”，说明引用了哪几篇

### 4. 任务闭环

- 提前准备好方案文件，现场只做“抽取—确认—完成一条”
- 完成后打开农事记录，展示自动生成的那条记录
- 统计页只停 2 秒，不要念所有数字

## 五、剪辑建议

- 片头 3 秒：标题 + 一句话定位，不要超过 5 秒
- 每个功能加 1 秒章节字幕：地块 / 天气 / Agent / 任务 / 知识库 / 工程
- 模型等待、页面加载用跳剪；不要全程 1.5 倍速，工具轨迹要让人看清
- 关键数字用后期放大或画圈：风速、降水、工具数、命中率
- 背景音乐音量压到 -25dB 左右，旁白清晰为主
- 导出：H.264 MP4，1080p，8–12 Mbps；文件过大可 6–8 Mbps
- 字幕：至少给关键结论加中文字幕，防止现场收音不清

## 六、发布前检查

- [ ] 没有出现 API Key、数据库密码、服务器账号
- [ ] 没有其他用户的手机号、姓名、地块数据
- [ ] 没有浏览器调试栏、控制台报错、开发环境提示
- [ ] 视频里的功能都真实跑通，没有用截图冒充运行
- [ ] Agent 回答里的天气、工具调用和界面一致
- [ ] 手机/投影上播放一遍，确认字能看清
- [ ] 保留原始录屏和项目文件，方便补录

## 七、常见翻车点

| 问题 | 处理 |
|---|---|
| Agent 超时/报错 | 提前预热一次；确认 `DEEPSEEK_API_KEY`、额度和网络；保留备用录屏 |
| 语音/PWA/推送用不了 | 需要 HTTPS；没有就跳过，不要假装演示 |
| 天气加载慢 | 提前打开一次，让 Redis 缓存命中 |
| 地图瓦片空白 | 提前加载目标区域，等瓦片缓存 |
| 任务抽取结果不理想 | 换一份结构清晰的方案文件，或现场只确认已有任务 |
| 录完发现字太小 | 浏览器缩放 100%，录制 1080p；后期对关键区域放大 |
| 视频太长 | 先保 Agent、任务、RAG 三段，其余压缩或删掉 |

## 八、3 分钟精简版

1. 首页：三块地、天气、预警（20 秒）
2. 问“明天能打药吗”，展开工具轨迹（60 秒）
3. 上传方案，确认任务，完成一条，展示记录（50 秒）
4. 文档提问，展示“参考知识”（30 秒）
5. 技术文档公式/代码/评测各停 3 秒，收尾（20 秒）
