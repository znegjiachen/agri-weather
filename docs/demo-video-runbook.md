# 演示视频完整流程（录制执行手册）

> 配套：[7 分钟演示稿 v2](demo-video-script-v2.md) · [拍摄指南](demo-video-guide.md) · [5 分钟现场答辩脚本](demo-script.md)
> 目标：按这份手册从零准备，一次录完「注册 → 圈地 → Agent 打药 → 方案任务 + RAG → 拍照 → 语音 → 推送 → MCP + 评测」全链路。

| 项目 | 取值 |

## 二、开录前 30 分钟准备

### 2.1 启动服务

```bash
# 后端（默认 8082）
cd agri-weather-server
export DB_PASSWORD=root
export JWT_SECRET=$(openssl rand -base64 32)
export DEEPSEEK_API_KEY=你的密钥
./mvnw spring-boot:run

# 前端（默认 5173）
cd weather-app-react
npm run dev
```

确认：

```bash
curl -s http://localhost:8082/api/agent/status
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5173/
```

`status` 里应看到 `configured: true`、`visionConfigured: true`、`asrConfigured: true`。

> 录音、PWA、Web Push 需要安全上下文。用 `localhost` 打开本机浏览器没问题；**手机要通过局域网 IP 访问，必须配 HTTPS**，否则手机端订阅不了推送。

### 2.2 开启 Web Push（要录推送就必做）

```bash
cd agri-weather-server
./mvnw -q org.codehaus.mojo:exec-maven-plugin:3.1.0:java \
  -Dexec.mainClass=com.agriweather.push.VapidKeyGenerator
```

把输出的 `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` 写进启动环境变量，再重启后端：

```bash
export VAPID_PUBLIC_KEY=...
export VAPID_PRIVATE_KEY=...
export VAPID_SUBJECT=mailto:you@example.com
```

### 2.3 演示账号与数据

**建议新注册一个干净账号**，不要用带 8 块地和测试命名的老账号。目标数据：

| 地块 | 作物 | 面积 | 播种日期 | 用途 |
|---|---|---|---|---|
| 湖南水稻田 | 水稻 | 约 400 亩 | 往前推 60–80 天（分蘖/拔节期） | 主演示：打药、RAG、方案任务 |
| 玉米试验田 | 玉米 | 约 50 亩 | 往前推 30 天 | 切换地块，体现多地块 |
| 番茄大棚 | 番茄 | 约 5 亩 | 往前推 45 天 | 换作物，体现阶段差异 |

- 至少主地块有真实边界（圈出来的多边形）
- 不要出现 `test`、`aaa`、`1 号田` 这类占位名
- 预警：先打开「预警中心 → 检查全部地块」，确保列表里有内容
- 任务：提前留 2–3 条今日/未来任务，录到「完成一条」时有东西可点

### 2.4 知识库

1. 侧栏「助农手」→ 智能体控制台 → 选中「湖南水稻田的助农手」
2. 打开「知识库」→ 上传 2–3 份：
   - `docs/knowledge-samples/rice/水稻稻瘟病防治指南.md`
   - `docs/knowledge-samples/rice/水稻品种选择与种子处理.md`
   - 可选：`docs/knowledge-samples/rice/水稻主要虫害识别与防治.pdf`
3. 在「检索测试」输入 `稻瘟病怎么防治`，确认能命中，再开录

### 2.5 素材文件

| 素材 | 路径 | 说明 |
|---|---|---|
| 种植方案 | `docs/plans/水稻早稻种植计划_2027.md` | 结构清晰，AI 抽取任务稳定 |
| 叶片照片 | 自备 1 张 | **提前走一次识图**，识别结果可讲再用；不准就换 |
| 知识库文档 | `docs/knowledge-samples/rice/` | 至少 2 份 |

### 2.6 手机 / 第二浏览器推送

- 与电脑登录**同一账号**
- 个人中心 →「预警通知」→ 开启，允许浏览器通知
- 先触发一次预警，确认手机能收到；收不到就先解决，别到录的时候赌

### 2.7 MCP 客户端

```bash
cd mcp-server
AGRI_USERNAME=你的用户名 AGRI_PASSWORD=你的密码 \
AGRI_API_BASE=http://localhost:8082 node server.mjs
```

Claude Desktop / Claude Code 配置：

```json
{
  "mcpServers": {
    "agri-weather": {
      "command": "node",
      "args": ["D:/智慧农业天气系统/mcp-server/server.mjs"],
      "env": {
        "AGRI_API_BASE": "http://localhost:8082",
        "AGRI_USERNAME": "你的用户名",
        "AGRI_PASSWORD": "你的密码"
      }
    }
  }
}
```

开录前先调用一次 `list_farmlands` 和 `get_weather`，确认工具能返回真实数据。

### 2.8 指标预热

在助农手里问 3–5 轮（打药、天气、知识库问题），让智能体控制台顶部的「AI 运行指标」非零：对话请求、工具调用、知识命中都要有数。

### 2.9 浏览器与录屏

- Chrome 独立用户配置，1920×1080，缩放 100%
- OBS：1080p / 30fps / H.264；麦克风单独音轨
- 第二块屏放逐字稿，不要放在录制屏
- 开录前强刷页面：`Ctrl+Shift+R`

## 三、完整录制流程（逐段操作）

### Scene 1｜0:00–0:20 注册与定位

**入口**：未登录状态打开 http://localhost:5173

**操作**
1. 在登录页点「立即注册」
2. 填用户名、密码、确认密码（手机号选填）
3. 点「注 册」
4. 自动进入桌面驾驶舱
5. 鼠标缓慢扫过：当前天气 → 地块卡片 → 7 日趋势 → 预警

**画面应出现**：首页三栏驾驶舱、地块下拉、今日待办与预警入口。

**旁白**
> 这是问田。一个地块级的农事气象助手。
>
> 它是一个能让作物从播种到收获的决策引擎。
>
>（停 0.5 秒）

**兜底**：账号已存在就直接登录；不要在现场纠结密码，提前把账号建好。

---

### Scene 2｜0:20–1:10 地图圈地

**入口**：首页「＋ 添加地块」，或侧栏「地图」→「地块地图」

**操作**
1. 首页点「＋ 添加地块」，地图页通常会自动进入圈地模式；没有就点「✏️ 圈地」
2. 点「🛰️ 卫星」确认是卫星底图
3. 在地块四角依次点击 4–6 个边界点，右上角会实时显示「N 点 · X 亩」
4. 点「✅ 完成」
5. 在「保存地块」表单里填：
   - 地块名称：`湖南水稻田`
   - 作物：`水稻`
   - 播种日期：往前 60–80 天
   - 土壤 / 灌溉：保留自动带出的值
6. 点「保存地块」
7. 回到地块列表，停 2 秒，展示面积、作物、助农手入口

**画面应出现**：多边形边界、服务端重算后的亩数、自动生成的专属助农手。

**旁白**
> 先建地块。在地图上点几个边界点，围成多边形，面积由服务端重算。
>
> 选好作物和播期，保存后，这块地会自动生成一个专属的助农手。后面的天气、预警、农事建议，都绑定到它。
>
>（停 0.5 秒）
>
> 土壤和灌溉建议也会按位置和作物自动带出。地图是卫星底图，边界随时能改。
>
> 切到地块列表，能看到作物、面积、种植天数和预警入口。多块地可以在左上角切换，驾驶舱跟着变。

**兜底**：瓦片空白就提前把目标区域拖一遍等缓存；点少于 3 个不能完成；圈得太小面积会难看，提前练一次。

---

### Scene 3｜1:10–2:40 Agent 工具轨迹（重点）

**入口**：侧栏「助农手」→ 智能体控制台 →「湖南水稻田的助农手」→ 进入对话（或右侧常驻浮窗）

**操作**
1. 直接粘贴问题：`明天适合给这块水稻打药吗？`
2. 发送，等思考/工具调用跑 2–3 秒
3. 点开「🧠 工作轨迹 · N 次工具调用」的「展开 ▼」
4. 慢速向下滚：第一轮思考 → 工具名 → 参数 → 耗时 → 下一轮
5. 在风速、降水两个数值处各停 1 秒
6. 追问：`那后天呢？`
7. 展示回答延续上文，不用重新报地块

**画面应出现**：`list_farmlands` / `get_weather` / `get_operation_advice` / `get_crop_stage` 等真实工具调用，参数里带地块 ID、经纬度，结果里有风速和降水。

**旁白**
> 现在问一个种地真会问的问题：明天适合给这块水稻打药吗？
>
> 模型没有直接编答案。它先确认地块，调用天气工具拿到风速和降水；再调农事规则，确认打药窗口；最后查生育期。
>
>（展开「工作轨迹」，慢速滚动，在工具名和耗时处停一下）
>
> 这里每一轮都有思考、工具名、参数和耗时。风速、降水都来自真实接口，不是模型想的。
>
>（停 0.5 秒）
>
> 规则判定风速超过上限，所以结论是不建议打药，并给出下一个可行窗口。
>
>（停 1 秒）
>
> 追问一句「那后天呢」，能看到上下文延续，不用再报一次地块。
>
> 工具报错时也一样：错误会作为结构化结果回给模型，让它换思路，不会把整轮对话打断。

**兜底**：提前问一次预热；第一次回答不理想就重录整段，不要拼接成另一个问题的答案；模型 7–14 秒很正常，剪辑把等待压到 2–3 秒，但别剪掉工具轨迹。

---

### Scene 4｜2:40–3:50 方案任务 + 知识库追问

**入口 A（方案任务）**：首页地块卡片「📒 记录」

**操作 A**
1. 点「湖南水稻田」卡片上的「📒 记录」
2. 切到「计划任务」tab
3. 点「📄 上传种植方案，生成任务」
4. 选 `docs/plans/水稻早稻种植计划_2027.md`
5. 等「正在解析方案…」结束，出现「识别到 N 条任务」和来源文件名
6. 点「确认保存为任务」
7. 展示时间轴上的播种、施肥、打药等任务
8. 完成其中一条，切到「农事记录」tab，展示自动生成的那条记录

**入口 B（知识库追问）**：回到该地块的助农手对话

**操作 B**
1. 问：`稻瘟病在什么温湿度条件下容易发生？`
2. 等回答，指向底部的「📚 参考知识：水稻稻瘟病防治指南…」
3. 口述：检索没命中就不注入；临时文档 7 天过期

**旁白**
> 方案怎么落地？上传一份种植方案，AI 把播种、施肥、打药、收获这些任务抽出来，每条带来源。
>
> 但它不会直接写进待办，要先人工确认。
>
>（确认保存，展示时间轴；完成一条，打开农事记录）
>
> 确认后才入库，到期提醒。完成一条，自动生成农事记录，并统计完成率和按时率。
>
>（停 0.5 秒）
>
> 再问一个知识库里的问题。回答下方会列出参考知识，说明这段来自哪份资料。
>
> 检索没命中就不注入，避免把无关内容塞给模型。临时文档保留七天，不进入长期知识库。

**兜底**：抽取结果不理想就换更规整的方案文件；知识库没命中就提前上传并跑检索测试；「完成率/按时率」只在统计区停 2 秒，不用念所有数字。

---

### Scene 5｜3:50–4:40 拍照识病

**入口**：同一助农手对话

**操作**
1. 点输入框左侧的「📷」/「📎」
2. 选一张提前验证过的叶片照片
3. 点发送
4. 等识别卡片出现：作物、生育期、健康状态、可见病害/虫害、置信度
5. 展示助农手把识别结果和地块天气结合后的建议

**画面应出现**：识别卡片 + 文本回答；低置信度时明确写「依据不足 / 建议补拍」。

**旁白**
> 再看识图。上传一张叶片照片，视觉模型先识别作物、生育期和可见病害，再把结果交给文本助手，结合地块天气给建议。
>
>（停 0.5 秒）
>
> 置信度低的时候，它会明确说依据不足，建议补拍叶片正反面和整株，而不是硬下结论。
>
> 具体用药只提醒按农药标签使用，不编造浓度和剂量。

**兜底**：识别不准就换图；也可以顺势讲「低置信度时提示补拍」，同样成立。

---

### Scene 6｜4:40–5:20 语音提问

**入口**：同一对话输入框

**操作**
1. 点「🎤」
2. 正常说 3–5 秒：`这种情况要打什么药？`
3. 再点一次停止
4. 等「正在识别…」结束，文字自动填入
5. 点发送
6. 展示回答接着上一张照片的上下文

**画面应出现**：录音时的「正在录音 + 音量条」；识别文字自动出现在输入框。

**旁白**
> 田里不方便打字，可以直接说。语音转成文字后，走的是同一套智能体、同一套工具和知识库。
>
>（识别结果自动填入并发送）
>
> 它接着上一张照片的上下文回答，不用重新描述病情。
>
>（停 0.5 秒）
>
> 语音、PWA 和推送都要求 HTTPS，这也是上线时统一配好的。

**兜底**：录音前确认系统输入设备是真正在用的麦克风，录音时看音量条是否跳动；识别失败会明确提示设备名，换设备或改 Windows 默认输入后重录这一段。实在不行就只用文字，但不要声称演示了语音。

---

### Scene 7｜5:20–6:00 预警与 Web Push

**入口**：侧栏「预警中心」；手机提前登录同一账号

**操作**
1. 个人中心 →「预警通知」→ 开启（手机和电脑都开）
2. 电脑进入「预警中心」
3. 点「检查全部地块」
4. 等检查完成，展示预警列表：冻害、热害、涝害、大风、病虫害
5. 手机同框弹出系统通知
6. 点通知，直达预警页
7. 指向页面说明「阈值推导，非官方发布，仅供参考」

**旁白**
> 预警不是气象局发布的，是平台按作物、生育期和未来二十四小时的温度、降水、风速算出来的阈值检查。后台每三十分钟自动跑一次。
>
>（停 1 秒，等手机通知）
>
> 点「检查全部地块」，手机立刻收到系统通知，点开直达预警页。
>
> 页面也写明了：非官方发布，仅供参考。

**兜底**：没有 HTTPS / VAPID 就**跳过这段并删掉旁白**；不要在视频里假装演示。手机收不到就先用同一台电脑的第二个浏览器窗口演示通知。

---

### Scene 8｜6:00–6:50 MCP 与 AI 安全评测

**入口 A**：Claude Desktop / Claude Code（已配置 agri-weather MCP）

**操作 A**
1. 展示工具列表：`list_farmlands`、`get_weather`、`get_farm_advice`、`search_crops` 等
2. 调用一次 `list_farmlands`，展示返回的地块
3. 调用一次 `get_weather`，展示真实风速/降水
4. 口述写操作规则：`confirm:false` 预览 → `confirm:true` 写入 → JSONL 审计日志

**入口 B**：侧栏「助农手」→ 智能体控制台顶部「AI 运行指标」

**操作 B**
1. 指向：对话请求、成功率、平均响应、工具调用、知识命中、👍/👎、推送成功/失败
2. 切到 `docs/ai-eval-report.md` 或技术文档评测页，展示 hit@5 = 10/10
3. 口述安全兜底：高毒/禁用农药、绝对化承诺追加提示；手机号/身份证自动隐去

**旁白**
> 同一套农事能力，也做成了标准 MCP Server。天气、地块、农事建议、作物检索都以 MCP 工具暴露，Claude Desktop 这类客户端可以直接调用。
>
>（停 0.5 秒）
>
> 写操作必须两段式确认：先预览，再写入；每次调用都记审计日志。
>
>（切回智能体控制台指标面板）
>
> AI 侧我们记录了对话请求、成功率、平均响应、工具调用和知识命中。RAG 评测 hit@5 是十比十，但样本只有十条，只作为链路验证，不写成田间效果。
>
>（停 0.5 秒）
>
> 输出侧有安全兜底：高风险农药、绝对化承诺会追加安全提示；手机号和身份证号会自动隐去。

**兜底**：MCP 客户端无响应就检查后端是否在跑、token/账号是否有效；备用方案是展示 `mcp-server/test.mjs` 的输出。指标全 0 说明没预热，录前先问 3–5 轮。

3. 停 1 秒再结束录制

**旁白**
> 问田把天气、地块、作物和 AI 接到同一条链路上。
>

## 四、剪辑与字幕

1. 先定死每段入点/出点，再按段贴旁白

## 六、常见问题

| 问题 | 处理 |
|---|---|
| Agent 超时/报错 | 提前预热；确认 `DEEPSEEK_API_KEY`、额度和网络；保留备用录屏 |
| 语音识别没文字 | 看录音音量条；确认系统输入设备和 Chrome 麦克风权限；失败会提示当前设备名 |
| 语音报 Connection reset | 后端已强制 HTTP/1.1 并重试一次；仍失败就重录这一段 |
| 手机收不到推送 | 必须 HTTPS + VAPID；本地可改用第二个浏览器窗口 |
| 地图瓦片空白 | 提前拖到目标区域等缓存 |
| 任务抽取结果差 | 换结构清晰的方案文件，或只确认已有任务 |
| 知识库没命中 | 提前上传并跑「检索测试」，命中后再录 |
| MCP 工具没响应 | 检查后端、账号密码/JWT；备用 `mcp-server/test.mjs` |
| 指标全是 0 | 录前先问 3–5 轮 |
