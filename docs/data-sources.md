# 问田数据来源与置信度说明

本文说明平台各类数据的来源、适用范围和置信度，供评委、试点农户和后续维护者核对。原则是：**能追溯到公开标准或权威资料的，标明出处；属于团队整理或规则推导的，明确标注，不冒充国家标准。**

## 1. 置信度口径

作物表 `crop_info` 使用 `data_source` 和 `confidence` 两个字段记录来源与置信度：

| 置信度 | 含义 | 使用建议 |
|---|---|---|
| `HIGH` | 直接来自国家标准、行业标准、产品登记标签或权威数据库，且已逐条核对 | 可直接作为决策依据 |
| `MEDIUM` | 综合公开标准、权威数据库和公开农技资料整理，经过交叉检查 | 可作为参考，关键农事仍建议结合当地农技员意见 |
| `LOW` | 团队根据公开资料整理，尚未逐条对照标准，或缺少区域试验验证 | 仅作提示，必须由当地农技员或田间观察复核 |

当前数据分级：

- 初始 34 种作物：`MEDIUM`，来源为 `QX/T 734—2024（播种温度参考）+ FAO EcoCrop + 公开农技资料`；
- 后续扩充的 30 种作物：`LOW`，来源为 `公开农技资料与地方栽培指南（团队整理，未逐条对照国标）`。

## 2. 分类数据来源

### 2.1 作物生长参数

| 数据项 | 来源 | 标准/依据 | 适用范围 | 置信度 |
|---|---|---|---|---|
| 适宜播种日平均气温 | 《关键农时气象服务通则》表 A.1；标准未列作物按常见栽培温度区间取值 | **QX/T 734—2024** | 主要粮食、油料、蔬菜和经济作物 | 标准覆盖作物 `HIGH`，其余 `MEDIUM` |
| 最佳播种温度区间 | 在适宜区间内按 FAO EcoCrop 四断点响应细化 | **FAO EcoCrop** 作物响应函数 | 播种适宜度评分 | `MEDIUM` |
| 生长周期、适宜温湿度、降水、光照 | 公开农技资料、地方栽培指南和团队整理 | 未逐条对照国标 | 作物档案与阶段判断 | 初始作物 `MEDIUM`，扩充作物 `LOW` |
| 霜冻/高温/涝害敏感标记 | 按作物常见灾害反应整理 | 团队整理 | 灾害规则提示 | `MEDIUM` / `LOW` |
| 播种期（按产区概括） | 公开农技资料与地方栽培指南 | 未逐条对照国标 | 播种期提示 | `MEDIUM` |

作物数据查询接口会直接返回 `dataSource` 和 `confidence`；Agent 的 `search_crop` 工具也会把这两个字段带回给模型，避免回答时把团队整理数据说成国家标准。

### 2.2 病虫害知识

| 数据项 | 来源 | 适用范围 | 置信度 |
|---|---|---|---|
| 病虫害名称、类型、高危生育期 | 公开植保资料与团队整理 | 水稻、小麦、玉米及常见蔬菜 | `MEDIUM` |
| 气象诱发条件（温度、湿度、连续阴雨） | 公开植保资料中的流行条件描述，参数化为区间 | 用于“当前天气是否利于发病”的提示 | `MEDIUM` |
| 防治方法 | 公开植保资料与绿色防控建议 | 农业防治、物理防治、生物防治优先 | `MEDIUM` |
| 推荐药剂 | 公开资料中的常见登记药剂类别 | 仅作方向性提示 | `MEDIUM` |

**药剂使用边界**：平台不提供浓度、剂量和复配方案；实际用药必须遵守《农药管理条例》、**GB/T 8321《农药合理使用准则》**系列标准和产品登记标签，并执行安全间隔期。Agent 回答中会提示“按当地登记作物、标签剂量和安全间隔期使用”。

病虫害数据不是全国普查数据，也不能替代当地植保站的病虫情报。`search_pest` 返回的是知识库匹配结果，不是田间诊断结论。

### 2.3 天气与预报

| 数据项 | 来源 | 许可/说明 | 置信度 |
|---|---|---|---|
| 实时天气、逐小时与 7 日预报 | [Open-Meteo](https://open-meteo.com/) | 数据许可 CC BY 4.0，使用时保留来源说明 | 取决于上游模型 |
| 国内备源 | 和风天气（配置 `QWEATHER_API_KEY` 后启用） | 按和风天气服务条款使用 | 取决于上游服务 |
| 天气缓存 | Redis / 本地缓存，30 分钟内视为新鲜，24 小时内可兜底 | 平台缓存，不改变原始数据 | 与上游一致 |

天气数据是网格预报，不是地块小气候实测。山区、河谷、设施大棚内的温度、湿度和风速可能与预报有偏差；涉及阈值判断时，平台会保留“以实地观测为准”的提示。

### 2.4 灾害预警与农事建议

| 数据项 | 来源 | 说明 | 置信度 |
|---|---|---|---|
| 冻害、热害、涝害、大风等风险 | 平台规则引擎：天气数据 + 作物敏感标记 + 阈值 | 规则由团队维护，详见 `AlertService` / `AdviceService` | `MEDIUM` |
| 适宜/不宜农事作业 | 平台规则引擎：天气 + 生育期 + 作业约束 | 不是国家标准结论，属于辅助决策 | `MEDIUM` |
| 预警等级 | 平台自定义分级，不等同于气象部门预警信号 | 仅用于站内提示和推送 | `MEDIUM` |

**重要区别**：平台预警是农事辅助提示，不是中国气象局或应急管理部门发布的官方气象灾害预警信号。出现官方预警时，以官方发布为准。

### 2.5 用户与业务数据

| 数据项 | 来源 | 说明 |
|---|---|---|
| 地块位置、面积、土壤、灌溉、作物与播期 | 用户录入 | 未经实地核验，置信度取决于用户填写 |
| 种植季、农事记录、计划任务 | 用户录入或方案抽取 | 方案抽取结果需用户确认后才入库 |
| 社区帖子与图片 | 用户发布 | 内容经白名单净化，不代表平台立场 |
| 对话历史、反馈 | 用户与模型交互产生 | 仅用于当前账号的连续对话和产品改进 |

用户数据默认只对本人可见；地块专属助农手还会限制跨地块访问。导出试点数据前应脱敏。

### 2.6 知识库与评测数据

| 数据项 | 来源 | 说明 |
|---|---|---|
| 内置知识文档 | 团队整理的公开农技资料 | 见 `docs/knowledge-samples/` 与 `BuiltInKnowledgeService` |
| 用户上传知识库 | 用户上传的 TXT/Markdown/PDF/Word | 只存提取文本，不代表平台认可其内容 |
| RAG 评测集 | 团队编写 | `docs/ai-eval-set.json`，10 条水稻问题 |
| Agent 评测集 | 团队编写 | `docs/agent-eval-set-v2.json`，45 条农户口吻问题 |
| 试点与对比数据 | 测试地块模拟运行 | 不是田间试验，不能外推为产量效果 |

## 3. 可追溯性设计

1. **库表字段**：`crop_info.data_source`、`crop_info.confidence` 随作物档案一起返回；
2. **Agent 工具**：`search_crop` 输出包含 `dataSource`、`confidence`，模型回答涉及作物参数时应说明依据；
3. **播种评分**：`CropService.getWeatherMatch` 在返回体中写明 `method` 和 `dataNote`（QX/T 734—2024 + FAO EcoCrop，水分未接入土壤墒情）；
4. **病虫害**：`search_pest` 固定返回药剂使用提示；
5. **气象数据**：前端与文档保留 Open-Meteo 来源说明；
6. **预警边界**：接口与文案明确“平台提示，不等同官方预警”。

## 4. 维护与复核

- 新增作物：必须同时填写 `data_source` 和 `confidence`，并在 Pull Request 中写明依据；
- 修改阈值或药剂建议：至少两人复核，优先引用国家标准、行业标准或当地植保站资料；
- 每年至少复核一次播种温度、灾害阈值和药剂类别；
- 发现标准更新或数据错误的，先改数据并补迁移，再更新本文档。

## 5. 已知局限

- 部分作物参数是团队整理的公开资料，未做区域试验；
- 天气是网格预报，未接入地块级气象站和土壤墒情；
- 病虫害知识库覆盖有限，不能替代当地植保站诊断；
- 预警分级是平台规则，不是官方预警信号；
- 试点数据为模拟运行，不能证明增产或减药效果。

如果评委或农户问“这个数据凭什么”，优先指向本文和作物接口返回的 `dataSource` / `confidence`，再说明对应标准的适用范围，不要用口头推断代替出处。
