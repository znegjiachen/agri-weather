# 答辩演示脚本（5 分钟版）

## 演示前检查

- 后端已配置 `DEEPSEEK_API_KEY`、`EMBEDDING_*`（可选）、`VAPID_*`
- 站点使用 HTTPS（Web Push、定位、Service Worker 必需）
- 账号已创建 3 块地，其中至少一块有边界、作物和播种日期
- 知识库已上传 2~3 份水稻/病害资料
- 手机或第二浏览器已登录同一账号，用于展示预警推送

## 演示顺序

### 1. 首页（30 秒）
- 展示桌面驾驶舱：当前地块、今日天气、7 日趋势、预警和农事建议
- 点开地块下拉，说明支持多地块切换和移动端布局
- 一句话：**“回答的是种地实际会问的问题，不是通用天气播报。”**

### 2. 地块与地图（40 秒）
- 打开地图，圈一块地，保存时自动带出土壤和灌溉建议
- 说明：面积按多边形服务端重算，土壤按位置估算，灌溉按作物推荐
- 回到地块列表，展示当前作物、预警和降水

### 3. 智能体工具调用（60 秒）
- 问：**“明天适合给水稻打药吗？”**
- 展开工作轨迹：模型先列地块 → 查天气 → 看到风速/降水 → 给出结论
- 强调：风速、降水来自真实接口，不是模型编的
- 追问：**“那后天呢？”**，展示上下文延续

### 4. 文档 RAG（50 秒）
- 上传一份《水稻病虫害防治指南》PDF/Word
- 问：**“这份方案里，稻瘟病在什么条件下容易发生？”**
- 展示回答下方的“参考知识/文档片段”，说明：上传时已切块建索引，提问只检索相关片段，不是整篇塞给模型
- 说明文档 7 天自动过期，可手动移除

### 5. 方案任务闭环（50 秒）
- 打开地块「📒 记录」→「计划任务」→ 上传一份种植方案
- 展示 AI 抽出的任务：播种、施肥、打药、收获及来源引用
- 点「确认保存为任务」，展示时间轴和待办
- 完成一条任务，说明自动生成农事记录
- 展示完成率/按时率/逾期/延误天数，强调“AI 从回答变成可执行、可追踪”

### 6. 多模态与语音（40 秒）
- 上传一张作物叶片照片，展示识别卡片（作物、阶段、健康状态、问题）
- 用麦克风问：**“这种情况要打什么药？”**
- 强调：语音转文字后仍走同一套文本智能体，田间不用打字

### 7. 预警与 Web Push（40 秒）
- 打开预警中心，说明后台每 30 分钟自动检查
- 在个人中心开启「预警通知」
- 点「检查全部地块」触发预警，展示手机/第二浏览器收到系统通知
- 点通知直达预警页
- 说明：预警是阈值推导，页面已标注“非官方发布，仅供参考”

### 8. AI 安全、反馈与指标（30 秒）
- 在回答下方点 👍/👎，说明反馈会入库用于评测
- 打开 `/api/agent/metrics` 或展示接口返回：请求数、成功率、平均延迟、工具调用数、知识命中、文档轮次、安全提示次数、点赞/点踩
- 说明安全兜底：高风险农药/绝对化承诺会自动追加安全提示

### 9. MCP（20 秒，可选）
- 展示 `mcp-server/` 配置：天气、地块、农事建议、作物检索已封装为标准 MCP tools
- 一句话：**“不仅能在站内用，其他 MCP 客户端也能调用这套农事工具。”**

## 收尾话术（20 秒）

> 问田把天气、地块、作物模型和 AI 助手接到同一条链路里：  
> 农户问一句“明天能打药吗”，背后是真实地块、真实天气、可追溯的工具调用和可检索的农技资料。  
> 我们的目标不是做一个聊天机器人，而是让小农户也能用上过去只有规模农场才有的农艺和气象服务。

## 常见提问准备

| 问题 | 回答要点 |
|---|---|
| 数据权威性 | 天气来自 Open-Meteo，可选和风天气备源；预警是阈值推导，页面已明确非官方发布 |
| 大模型幻觉 | 工具结果注入 + 文档边界标记 + 安全提示 + 用户反馈闭环；不保证 100% 正确 |
| 和竞品差异 | 地块级 Agent + 真实农事工具 + 多模态 + 可检索资料 + Web Push，不是通用问答 |
| 商业模式 | 合作社/农服组织 SaaS、农技推广部门项目制、农险增值服务；先做区域试点 |
| 隐私 | 手机号和地区可编辑；对话/文档可清理；文档 7 天过期；MCP 复用 JWT 权限 |

## 3 分钟精简版

1. 首页：真实地块 + 天气 + 预警
2. 问“明天能打药吗”，展示工具轨迹
3. 上传种植方案，追问文档内容，展示 RAG
4. 拍照识病 + 语音提问
5. 手机收到预警推送
6. 展示反馈和指标，收尾社会价值
