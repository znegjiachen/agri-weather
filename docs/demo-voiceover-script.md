# 演示视频旁白稿（7 分钟版）

配套：[演示视频拍摄指南](demo-video-guide.md)

## 使用说明

- 每个场景单独录一段，文件名按 `scene1`、`scene2` 编号，剪辑时按时间码对齐。
- 正常语速约 230–250 字/分钟，整稿约 1700 字，接近 7 分钟。
- 括号里是停顿和操作提示，不要念出来。
- 术语读法：问田读 `wèn tián`；助农手读 `zhù nóng shǒu`；稻瘟病读 `dào wēn bìng`；阈值读 `yù zhí`；RAG 说“检索增强”；SSE 说“流式输出”；GDD 说“积温”。

## Scene 1｜0:00–0:25 首页

（画面：桌面驾驶舱，鼠标轻扫天气、地块、预警）

这是问田。它不只想告诉你明天什么天气。

它要回答的是：这块地，明天能不能打药；水稻，该不该防冻。

（停 0.5 秒）

---

## Scene 2｜0:25–1:15 地块与地图

（画面：打开地图，缓慢圈地，保存，回到地块列表）

先建地块。点几个边界点，围成多边形，系统自动算亩数。再选作物和播期。

保存后，这块地会有一个自己的助农手。

（停 0.5 秒）

地图是卫星底图，边界可以随时改。地块列表里能看到作物、面积、种植天数和预警入口。

---

## Scene 3｜1:15–1:55 驾驶舱与预警

（画面：切换地块，打开 7 日趋势，进入预警中心）

回到驾驶舱。左边是当前地块的实时天气，中间是未来七天趋势，右边是预警和今日农事。

点开预警中心。这里的预警不是气象局发布的，是平台按作物、生育期和未来 24 小时的温度、降水、风速算出来的。页面也写明了，只作参考。

（停 0.5 秒）

---

## Scene 4｜1:55–3:25 Agent 工具轨迹

（画面：打开助农手，粘贴问题，发送，等待，展开“工作轨迹”）

现在问它一个种地会问的问题：明天适合给这块水稻打药吗？

模型没有直接编答案。它先调用天气工具，拿到风速和降水；再调农事规则，确认打药窗口；最后查生育期。

（展开工作轨迹，慢速滚动）

这里能看到每一轮的思考、调用了哪个工具、参数是什么、花了多久。风速 21.6 公里每小时，已经超过平台规则，所以回答是不建议打药。

（停 1 秒）

如果工具报错，错误会作为 JSON 回给模型，让它换思路，不会把整轮对话打断。

---

## Scene 5｜3:25–4:05 多模态（可选）

（画面：上传叶片照片，展示识别卡片）

再看识图。上传一张叶片照片，视觉模型先识别植物、生育期和可见病害，再把结果交给文本助手，结合地块天气给建议。

置信度低的时候，它会明确提示补拍，而不是硬下结论。

---

## Scene 6｜4:05–4:45 播种适配

（画面：打开作物页，选择作物，展示条件检测）

播种适配不是查一张表。选作物、选地块，系统把计划播期和实时气象对齐，分别看温度、降水、光照和湿度，再给一个综合匹配度。

（停 0.5 秒）

温度参考 QX/T 734 的播种界限温度，降水按 FAO EcoCrop 的日均需水折算。每项都有权重，严重不适宜的项会压低总分。

---

## Scene 7｜4:45–5:40 方案任务闭环

（画面：上传方案，展示抽取结果，确认，完成一条任务，打开农事记录）

方案怎么落地？上传一份种植方案，AI 把里面的农事任务抽出来。但不会直接写进待办，要先人工确认。

（停 0.5 秒）

确认后，任务进入时间轴，到期会提醒。完成一条，系统自动生成农事记录，并统计完成率和按时率。

这一步很关键：AI 的输出不是停在聊天框，而是变成可执行、可追踪的农事动作。

---

## Scene 8｜5:40–6:25 知识库与 RAG

（画面：上传资料，提问，展示“参考知识”）

每块地的知识库是独立的。上传 PDF、Word 或 Markdown，系统切块建索引；提问时只检索相关片段，标注引用了哪几篇。

（停 0.5 秒）

没有命中就不注入，避免把无关内容塞给模型。对话里的临时文档保留 7 天，不进入长期知识库。

---

## Scene 9｜6:25–7:05 工程与评测

（画面：技术文档公式、代码、评测表各停 2–3 秒）

工程上，CI 会跑后端测试、全新数据库迁移和前端严格类型检查；AI 评测有检索命中率、Agent 场景和有无工具的对照。

（停 0.5 秒）

样本还小，所以文档只写成链路验证，不写成田间效果。这一点我们在局限里写得很清楚。

---

## Scene 10｜7:05–7:30 收尾

（画面：回到驾驶舱完整画面）

问田把天气、地块、作物和 AI 助手接到同一条链路上。

下一步，是把它放进真实田间使用。

（停 1 秒，结尾）

# 三种配音方式

## 方式一：自己录（推荐）

- 设备：手机耳机麦或 USB 麦克风即可，离嘴 15–20 厘米，加个海绵套
- 环境：小房间、关窗、关空调，床上或衣柜前录音更干净
- 姿态：站着录，气息更稳；每段录 2–3 遍，挑最自然的一遍
- 语速：比平时慢一点，关键数字后停半秒
- 后期：降噪、压缩、响度归一化到 -16 LUFS；背景音乐压到 -25 到 -30 dB

## 方式二：剪映文本朗读（最省事）

- 把每一场旁白粘贴到剪映文本，使用“文本朗读”
- 选一个自然的中文音色，语速 1.0–1.05，不要用夸张的营销音色
- 逐场景生成音频，再按时间码拖到视频轨道
- 生成后人工听一遍，改掉多音字和断句错误

## 方式三：Edge TTS（免费、可批量）

安装：

```bash
pip install edge-tts
```

生成单场景：

```bash
edge-tts --voice zh-CN-YunxiNeural --rate=+0% --pitch=-2Hz \
  --text "这是问田。它不只想告诉你明天什么天气。" \
  --write-media scene1.mp3
```

常用中文音色：

- `zh-CN-XiaoxiaoNeural`：女声，自然，适合讲解
- `zh-CN-YunxiNeural`：男声，偏年轻，适合技术演示
- `zh-CN-YunjianNeural`：男声，偏新闻播报

建议：每个场景单独生成，方便对齐；不要把整篇一次生成，否则中间出错要重来。

## 方式四：Azure / 讯飞 / 腾讯云 TTS

需要更自然的停顿和情绪时使用。可以用 SSML 在关键句后加 `<break time="500ms"/>`，例如：

```xml
<speak version="1.0" xml:lang="zh-CN">
  <voice name="zh-CN-XiaoxiaoNeural">
    这是问田。<break time="500ms"/>
    它要回答的是：这块地，明天能不能打药。
  </voice>
</speak>
```

不要使用未经授权的真人声音克隆；比赛材料里建议用自己录音或平台提供的标准音色。

# 对齐与混音

1. 先剪好画面，定死每个场景的入点和出点
2. 按场景生成/录制旁白，逐段拖到对应画面
3. 以旁白为准微调画面：关键工具轨迹出现时，旁白正好说到“调用了哪个工具”
4. 旁白之间留 0.3–0.5 秒，不要全程无缝，听起来更自然
5. 背景音乐选无版权轻音乐，音量压到旁白的 20% 以下
6. 导出前用手机外放听一遍，确认没有爆音、齿音和音量忽大忽小

# 字幕

- 先用剪映/PR 自动识别字幕，再人工改术语：助农手、稻瘟病、阈值、检索增强、积温
- 关键数字加粗或放大：风速 21.6 km/h、3 个工具、hit@5 10/10
- 不要把整段旁白都做成大字幕，保留底部两行即可
